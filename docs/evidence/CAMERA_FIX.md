# Camera input correction

The production browser check reported that five Right-arrow taps produced no visible camera movement at zoom 1. The existing source moved the camera only when `Key.isDown` was true during `GameScene.update`. Phaser's keyboard plugin processes queued keydown and keyup events before the next scene update; `Key.onUp` clears both `isDown` and `_justDown`. A tap completed within that interval therefore has no movement. Replacing polling with `JustDown` alone would retain that failure.

`GameScene.key` now applies a 48-screen-pixel impulse on each non-repeating camera keydown, divided by the current zoom. Existing held-key movement remains unchanged. Arrows and W/S/D pan; A pans only with no selection and still enters attack-move with a selection. Ctrl, Meta and Alt combinations receive no tap impulse. Camera keys remain usable while paused or after a match result, while the existing gameplay-order guard still blocks attack/ability/stop keys in those states. Browser key-repeat does not add more impulses.

Middle drag now cancels any pending left-button selection drag when it starts. Pointer movement verifies that the middle button remains held. A release outside the canvas clears drag state through Phaser's `pointerupoutside` event; window blur also clears it. The added window listener is removed on scene shutdown. The installed Phaser source confirms that an outside release emits `pointerupoutside` instead of the ordinary `pointerup` event, which explains how the previous handler could leave a stale pan active.

`npx tsc --noEmit` passed after this source change. No production build was run and the active production match was not replaced. This is source analysis and type-check evidence only; browser verification is pending.

The next production browser check should use an interior camera position at zoom 1. A Right tap should pan about 48 screen pixels, repeated taps should move consistently, and holding a camera key should continue moving smoothly after its initial impulse. With units selected, A should arm attack-move without panning. Middle-drag release outside the canvas and window blur should stop movement, with later hover motion leaving the camera still. At minimum zoom, the visible world may be wider than the camera bounds; bound clamping can correctly prevent horizontal movement and must not be mistaken for lost input.

## Browser verification

Production bundle `index-CtYLjB1s.js` was loaded in the browser at 1920×1080. Short Right and Down taps visibly moved the headquarters up and left on the screen; `camera-arrow-taps.json` records camera scroll 928,112 at zoom1. Space returned home. F2 selected the Ironjaw, and A followed by a ground click produced the HUD attackMove order without a camera pan. After pausing, one Right tap changed scroll from640 to688 while match time stayed46.75s; `camera-paused-pan.json` records that state. These checks verify tap navigation and preservation of attack-move and paused camera behavior. Held-button middle dragging and outside release remain unverified through the available high-level browser API; their changes have source review and TypeScript checking only.
