# Browser integration check

The final production build ran at 1280 × 720 on the local preview. Setup rejected -1, 1.5 and an empty seed with the visible message “Enter a whole-number seed from 0 to 4294967295.” A valid seed 4127 started Automata versus Fairies on medium terrain.

Through ordinary UI clicks, an Assembler ordered an Assembly Hall, which completed at full health. The hall recruited a Prism Archer. A worker gathered ore and then crystal; the HUD reached 36 crystal. Clicking Ward Engine reduced wood 174 to 54, ore 148 to 68 and crystal 36 to 24, and displayed its recruitment queue. This exercised the third resource through gathering, deposit, affordability and spending. Early crystal clicks did not issue orders while the deposit was near the lower HUD; panning down exposed it and the gathering order succeeded.

The match ended in defeat at 352.75 simulation seconds before the Ward Engine completed. This was an integration exercise with time spent documenting, not normal pacing evidence or proof of every unit's browser ability. New skirmish returned to all six faction choices with seed 4127 retained. Simulation and terminal runs supply complete roster and ability evidence separately.

The [81 telemetry samples](browser-automata-fairies.ndjson) and [summary](browser-summary.json) record match state, completed construction, ranged-unit presence, crystal income, the special queue and the terminal result. Telemetry does not establish which UI actions preceded a state. The UI observations above were recorded during manual browser control. No resources, units, orders or outcomes were injected through QA.
