The reviewed file is `/tmp/ovf-root-feature63-r3-preparation-551FgMyq/authenticate-prelaunch.py`, 4,369 bytes and 28 lines, SHA-256 `8626c914b0b717f6836a20a3fe55d261ddbfeb562eae7ffda749e60818fdf870`.

Its field and launcher shape still fit. With `PHASE=r7`, it reconstructs the R7 prefix and heavy-slot literal used by the reviewed binding utility, then applies the `launcherChanges` map in the same order. The assignment still supplies the ten binding, script, and executable descriptors the script checks. Its expected inventory counts remain 966 source, 570 product, 397 protected dist, 398 web, 22 server, 114 Playwright, and 303 Chromium. Nothing in the R7 output schema creates a simple field mismatch.

The first blocker is that all authentication decisions use `assert`. The script never rejects optimized Python. If it runs under `python -O` or with `PYTHONOPTIMIZE` set, those checks disappear, but line 28 can still write `root-independent-prelaunch-readback.json`. A hardened version must reject `sys.flags.optimize != 0`, clear `PYTHONOPTIMIZE` in its invocation environment, and use an always-active `require()` function for every security decision.

The second blocker is the missing root trust anchor. The script accepts only an output directory and phase. It does not require the expected digest of `root-binding-readback.json`, `capture-assignment.json`, the R7 independent review, or the launcher template. The readback therefore defines its own output inventory, control path, launcher path, and launcher changes; the assignment defines the binding and executable descriptors that are later accepted. A self-consistent wrong or altered directory can define what passes. The R7 version needs root-supplied canonical paths and digests for the binding readback, assignment, independent review, and launcher template, plus the expected future source pin. It should require `PHASE == r7` and verify the review schema, pass status, `runtimeExecuted: false`, and exact five roles before trusting any generated record.

The third blocker is separate parsing and verification reads. `desc()` calls `stat()` and `read_bytes()` independently. The assignment and readback are parsed directly without a pinned descriptor. Source, build, browser, product, protected, and launcher-template definitions are also parsed or used through reads separate from their later digest checks. This recreates the input race removed from the R7 binding utility. The replacement should use the same single-descriptor pattern: canonical path, `O_NOFOLLOW`, regular-file and size checks, before/after/path identity equality, one byte buffer, digest verification, and parsing from that verified buffer. Retained definitions should be cached and reused.

The protected preview checks and old SQLite custody metadata are compatible with the retained workflow, but they are live checks and were not performed here. After root imports the three reviewed proof scripts, the future assignment must use the resulting commit, and both checkouts must be at that pin with clean tracked state. The product and protected preview must remain untouched.

The earlier R7 static PASS remains valid for the packet and binding utility. This result blocks only reuse of the old R3 prelaunch authenticator as an independent R7 trust gate. Prepare a hardened external R7 prelaunch authenticator, review its exact bytes, and run it only after the reviewed binding utility succeeds.
