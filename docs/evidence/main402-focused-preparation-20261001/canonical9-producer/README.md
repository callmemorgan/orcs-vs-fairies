## Integration API

It requires a fresh output directory and a full 40-character future integration pin. It asserts SAVE4 and rules 4.0.2, authors all initial conditions, starts the recorder afterward, requires zero recorded actions and zero initial ticks/time, and validates the complete session/save round-trip. It writes nine encounter JSON files and `canonical-main-manifest.json`, then returns the manifest. Importing the module has no generation branch.

`candidate/scripts/acceptance/canonical-main-smoke.mjs` exports `CANONICAL_CASES` and `runCanonicalTacticsSmoke(ctx)`. Root's thin wrapper must import that filename. The driver receives the existing `createNativeContext`; it creates no browser, server, source freeze, build, fixture set or observer. Its only gameplay changes are native DOM, pointer and keyboard input. Browser predicates read `window.rts`.

The driver returns `completed`, `caseNames`, `exports`, `continuations`, `results` and `requiredEventAudits`. Its native completion field describes those nine encounters only. Root must still inspect screenshots, transient combat chronology and continuation suffixes before admission. Partial progress is retained as `ctx.evidence.canonicalProgress`; a failure retains the active case's samples/events when possible. A new output directory is required for a retry.

## Reviewable changes

The generator discloses all authored positions, health, facing, orders, passive cooldowns, removed actors/resources/sites and retained entrances. Morale attackers begin one normal weapon cooldown period from ready, currently 3.8 seconds, so a native command can be recorded before firing. The driver retains `morale-native-attack-before-volley`: the accepted seven-engine attack, full squad health/morale 100/recentLoss zero and no pending shell. That checkpoint establishes chronology; it does not impose a new gameplay rule.

Morale admission uses the observed damage/casualty sequence and a living wounded retreater with a close living ally. It does not require a predicted damage total or all four ranged deaths. Replay action ticks are derived from the initial tick and preceding advance actions because command actions have no tick field. Single-unit Hold restores its acting selection through the paused owned-troop list. The morale case resumes, focuses empty ground and uses F2 to restore exactly its seven engines, because battlefield selection and F2 are blocked during pause. Formation and attack helpers resume before battlefield multi-selection. Native Hold defends in range; the short interval and subsequent pause must preserve the observed first-hit HP, which the driver checks.

Native continuous ground coordinates are retained as accepted. Formation anchors must equal the recorded move coordinates; the requested point is only a pointer tolerance check. No native save values are normalized. Complete `.game`, including runtime, is compared through the existing context and contract.
