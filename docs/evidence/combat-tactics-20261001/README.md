# Combat tactics verification

The combat implementation adds features 1, 2 and 4–10 to the authoritative simulation. Feature 3 uses the separate world/elevation implementation and is pending integration here. The first combat foundation is commit `3269270`; subsequent verification fixes cavalry momentum that did not decay while holding position.

Run the committed encounter tests with `npx vitest run tests/combat-tactics.test.ts`. The scenarios use the real command validator, `issueCommand`, `stepGame`, strict saves, observations and replay engine. They isolate weapons with long defender cooldowns so damage comparisons have one cause. They do not modify state while measuring an attack, movement or capture channel. Initial fixture setup assigns formations, units, positions and health as an authored tactical scenario would.

The 22 encounter checks prove all four formation layouts with mixed troops, routing around a depot, stable slots under reversed input and regrouping after a combat casualty. Front, side and rear shots deal 12, 15 and 18 HP against the same held defender; turning it changes the damage. Wounded isolated troops retreat, allied support restores morale, and three surrounding captors take a broken fighter without healing it. A save during retreat continues with the same checksum.

The shield encounters verify frontal protection, rear bypass, changed facing, allied-player support and depletion. They verify the actual guard energy spent and HP lost. Rocks and buildings reduce ranged damage, melee bypasses cover, and destroying a covering depot through artillery restores the unprotected ranged hit.

Siege shells travel before impact, hit nearby allies when friendly fire is enabled, and exclude allies when it is disabled. Saving during flight preserves the later impacts and checksum. Cavalry gains impact through movement, loses it after stopping or a sharp turn, and takes a counterhit from frontal braced pikes; a rear charge retains its impact. Melee attacks can kill a siege crew while leaving the engine intact. The engine becomes neutral, rejects its former owner's commands and can be captured through a four-second channel. Channel save/resume, enemy contesting, original engine definition and subsequent movement by the new owner are checked.

Ambush troops in standing trees withhold attacks and disappear from enemy observations until the selected trigger. A cavalry scout detects them at close range. Manual release and loss of the concealing wood expose them. Enemy observations omit the private ambush condition. A replay containing formation movement, concealment and combat reaches the same saved checksum.

`verified-regressions.log` covers the encounter checks and existing saves, team observations, queued orders, HUD health, faction rules and simulation checks. The earlier default-timeout run had 247 passes and two 5-second AI timeouts; the isolated 30-second rerun passed both, and the final combined run uses that same timeout. The failed pre-fix charge assertion is retained in `encounter-before-charge-stop-fix.log`.

The separate TacticsTools browser proof uses mounted Phaser GameScene and normal panel buttons plus a native battlefield right-click. Its fixture has buttons for selecting scenario actors and preparing their initial positions. It proves the panel command path and UI permission gates; it does not establish integration with the main application, online observations, final artwork or the elevation branch. Those remain required before the overall feature ledger can mark this slice verified.

Root integration must use the canonical match-rules friendly-fire field, resolve captured definitions through the content registry, retain the original faction for artwork, merge environment/elevation/relic damage once, and propagate level through every distance, projectile and fog check. The strict optional tactical save fields need inclusion in the next combined save schema and old replay histories must not be claimed compatible with changed rules.
