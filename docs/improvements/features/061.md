# 061: selectable map layouts

The requirement is distinct river-crossing, plains and mountain-pass battlefields. The menu now selects those layouts or the original seeded wilderness. Plains have open ground and direct/flank roads; a river band has three designed crossings; a mountain wall has two passes and roads that turn along it. Seeded symmetric deposits stay accessible in each layout. Starting a match applies the layout before spawning either army.

`generateMap(seed, size, improvements)` accepts the same optional JSON map options as `createGame`. The registered `feature-061` option is `{ "layout": "plains" | "river" | "mountain" }`. Omitting it preserves the old generator. Clients also return their options through the agreed `learning-map-options` event so feature 009 can reproduce the selected map. Map transforms run in feature-ID order, and selected maps receive connectivity/resource validation.

Claude Opus 5.5 with the default `opus[1m]`, xhigh settings completed two cleanup passes. The first factored repeated positions, feature IDs and descriptions; its review found that repeated strokes could replace bridge tiles with buildable road. I corrected that behavior and added a river-band regression check, then ran a second complete cleanup. It simplified painting and DOM/test code. Both manifests have no denials, HEAD/index changes or out-of-scope paths. The second pass's `new Option` construction failed the happy-dom match-start test; I restored the equivalent portable `createElement('option')` construction and added a client-flow test. This last mechanical correction changes neither layouts nor gameplay.
